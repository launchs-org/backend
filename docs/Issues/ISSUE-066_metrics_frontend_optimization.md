# ISSUE-066 フロントエンド: メトリクスグラフの表示期間変更・ダウンサンプリング・ダウンロード機能

## 親 Issue
ISSUE-064

## 背景・動機

ISSUE-065でバックエンドの保持期間が3日になるため、フロントエンドの「1週間」表示選択肢は意味を失う。
また、30秒間隔・24時間表示でも2,880ポイントが返ってくるためグラフがカクカクする問題がある。
表示時は期間に応じてデータを間引き、生データが必要なユーザーにはダウンロード機能で提供する。

## 概要

メトリクスグラフの表示期間の最長選択肢を1週間から3日に変更する。
グラフ描画時は期間ごとに決められた粒度でデータを間引いてレンダリングする。
生データのダウンロード機能を追加し、詳細なデータが必要なユーザーに対応する。

## ダウンサンプリング仕様

APIから全データを受け取った上で、フロントエンド側で以下の粒度に間引いてグラフを描画する。

| 表示期間 | 間引き粒度 | 表示ポイント数（目安） |
|---------|-----------|---------------------|
| 1時間   | 30秒（間引きなし） | 120ポイント |
| 3時間   | 90秒（3件に1件）  | 120ポイント |
| 24時間  | 12分（24件に1件） | 120ポイント |
| 3日     | 36分（72件に1件） | 120ポイント |

間引きロジック：`データ配列をN件ごとに1件サンプリング`（先頭要素を代表値として採用）

## 変更ファイル一覧（フロントエンドリポジトリ）

- メトリクスグラフコンポーネント（編集）
    - **何を**: 表示期間の選択肢から「1週間」を削除し「3日」を追加する。期間選択に応じてダウンサンプリング関数を通したデータをグラフに渡すように変更する。
    - **なぜ**: バックエンドの保持期間変更に合わせてUIを整合させ、グラフのカクカクを解消するため

- メトリクスダウンサンプリングユーティリティ（新規作成）
    - **何を**: 表示期間を受け取り、対応するサンプリング間隔でデータ配列を間引いて返す関数を実装する。
    - **なぜ**: グラフ描画用のデータ削減ロジックをコンポーネントから分離してテスト可能にするため

- メトリクスダウンロードボタンコンポーネント（新規作成）
    - **何を**: 現在取得済みのメトリクスデータをCSV形式に変換してダウンロードするボタンを実装する。CSVカラムは `recorded_at, pod_name, cpu_millicores, memory_bytes, ready_replicas, total_replicas`。
    - **なぜ**: 詳細な生データが必要なユーザーに間引きなしのデータを提供するため

## テスト確認項目

- [ ] 表示期間選択肢に「1週間」が存在せず「3日」が存在すること
- [ ] 1時間表示でグラフポイント数が約120であること
- [ ] 3時間表示でグラフポイント数が約120であること（3件に1件サンプリング）
- [ ] 24時間表示でグラフがカクカクしないこと
- [ ] 3日表示でグラフがカクカクしないこと
- [ ] ダウンロードボタンを押すとCSVファイルがダウンロードされること
- [ ] ダウンロードCSVに全レコード（間引きなし）が含まれること
