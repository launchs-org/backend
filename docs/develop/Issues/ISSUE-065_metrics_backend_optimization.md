# ISSUE-065 バックエンド: メトリクス収集間隔・保持期間・API上限の変更

## 親 Issue
ISSUE-064

## 背景・動機

現在5秒間隔・7日保持の設定では、1デプロイメントあたり最大120,960レコードが蓄積される。
60ユーザー・1ユーザーあたり25デプロイメント規模を想定すると約1.8億レコードになり、スケールしない。
30秒間隔・3日保持に変更することで最大8,640レコード/デプロイメントとなり、60ユーザー規模で約1,300万レコードに抑えられる。

## 概要

メトリクス収集のポーリング間隔を5秒から30秒に変更し、DBの保持期間を7日から3日に短縮する。
あわせてAPIが返すlimit上限を8,640（30秒×8,640=3日分）に変更する。

## 変更ファイル一覧

- `app/src/k8s/watch_metrics.go`（編集）
    - **何を**: `time.NewTicker` の間隔を `5 * time.Second` から `30 * time.Second` に変更する。`DeleteOlderThan` に渡す保持期間を `AddDate(0, 0, -7)` から `AddDate(0, 0, -3)` に変更する。
    - **なぜ**: 収集頻度と保持期間がレコード数の根本的な規定要因であり、ここを変えることで蓄積量を大幅に削減できるため

- `app/src/handler/metrics_handler.go`（編集）
    - **何を**: `MaxLimit` 定数を `120960`（1週間分）から `8640`（3日分）に変更する。
    - **なぜ**: APIが返すデータ量の上限をDBの保持期間に合わせて制限するため
